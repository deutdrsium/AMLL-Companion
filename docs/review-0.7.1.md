# 0.7.1 review 与验证

本轮从用户提供的 0.6.14 性能日志出发，检查应用自有代码的检索、匹配、元数据过滤、质量排序、翻译／对唱合并、播放时钟、React 生命周期、窗口布局、WPF/WebView2 通信、SMTC 适配、Rust 提供方适配、诊断及打包路径。没有重写第三方库或重新启用实验性对齐功能。

## 已修复的问题

| 严重度 | 问题及证据 | 处理 |
| --- | --- | --- |
| 高 | 渐进检索每次排序都重新扫描、过滤整份歌词；CPU profile 的主要采样落在质量评分、元数据匹配及繁简转换 | 按解析结果与身份缓存评分，替换数组／身份变化时失效；不修改公共评分结果，不缓存失败 |
| 高 | 开头正文结束后仍对整首歌计算署名规则 | 在正文非边界行直接返回；没有标题分隔符时不进行标题身份转换 |
| 高 | 所有候选两两补全，连逐词质量不可能胜出的底本也参与 | 只补全最高逐词质量层，保留全部合格 donor；保持原始稳定顺序，并在批次间让出事件循环 |
| 中 | 句子近似匹配为完整编辑距离，尽管最多只允许两个编辑 | 改为带宽受阈值限制的动态规划，与完整距离的 120 个确定性变体对照 |
| 中 | 别名查询覆盖已解析条目，最终选择重复解析相同版本 | 保留已解析候选及其评分；失败条目仍可重试 |
| 中 | 手动选择先清空当前歌词，下载失败后不能恢复 | 成功后再替换，失败保留当前歌词并显示错误 |
| 中 | 并发媒体命令共用一个异步 StreamWriter | 在共享发送方法串行化写入，原生测试同时发送 20 个控制请求 |
| 中 | 空目录条目或空歌手对象可中断整批有效结果 | 在提供方、AMLL、LRCLIB 边界跳过坏条目，错误响应结构仍作为错误报告 |
| 中 | 提供方只检查行起止时间，负数／倒序单词时间仍可能传入并使渲染器抛错 | 用共用时间戳校验覆盖提供方、TTML／LRCLIB 加载及网页 LRC，在展示前拒绝此版本 |
| 中 | 合唱作品只要匹配一位歌手就能通过；网页署名也存在同类问题 | 核对全部具名艺人及组合署名，保留完整乐队名称与单艺人已验证别名；多艺人扁平别名无法唯一归属时不自动猜测 |
| 中 | 在旧发布目录增量打包会夹带旧资源；源码与界面 HTTP 版本分别硬编码 | 使用干净暂存目录、预检运行中文件、核对版本、生成校验文件；界面和 HTTP 使用实际版本 |
| 中 | 只显示首次结果，后续升级等待所有来源完成 | 就绪的更优合格版本立即自动升级；显示记录保存快照，手动选择仍取消自动检索 |
| 中 | 翻译补全合并原文行并改变原换行位置 | 匹配可跨行，但输出保留原文每行、words、时间和音译；整句译文只放一次，不猜测拆分 |
| 中 | React 包装组件以旧 currentTimeRef 重建，且布局弹簧尚未到达当前位置就开始淡入 | 在核心重建入口取实时时间；隐藏测量两帧，先固定布局再恢复弹簧和淡入 |

## 验证

- Node：95 个测试通过，包含新增缓存失效、评分不变性、完整署名、空目录条目、无效单词时间以及原有翻译／对唱／取消／时钟测试。
- 元数据：复测原来的 18 个有效真实版本，23/23 信息行、558/558 注入信息、612/612 格式位置组合被识别，正文零误删。
- 浏览器：首份歌词提前显示、慢来源未结束前无需点击版本列表即自动升级、手动选择取消后台任务、失败替换保留正文、规范名称／别名／手动纠正／缓存恢复、DPR 1.5 和九种窗口场景、普通／debug 过渡均通过。热替换测试先只推进播放时钟而不触发 React 更新，再检查重建入口时间及淡入可见行的位置变化（小于 8 CSS 像素）。
- Windows 原生：实际 SMTC 测试会话的发现、控制、并发写入、时钟推进、暂停、跳转、换歌、延迟封面、偏移保存、七种窗口尺寸、浮窗、置顶、全屏和断开测试通过。
- Rust：适配器的两个酷我双语解析测试通过，使用锁文件离线编译。
- Python：保留的实验性对齐纯函数七项测试通过；C# 音频目录选择及公网 URL/DNS 地址限制测试通过。没有执行模型下载或完整声学推理。
- 性能：80 个真实缓存版本的渐进排序与 0.6.14 排序逐次对照，全部顺序相同，约 6405 毫秒降至 18 毫秒；详见独立 JSON 报告。80 个合成匹配候选在实际前端逐步到达时，DPR 1.5、无专辑背景下最长帧间隔约 56 毫秒，95% 在 7.1 毫秒内；不是用户原日志的逐请求录制回放。

0.7.1 打包程序已验证普通模式不生成诊断日志，`--debug` 模式能记录人为制造的卡顿及资源采样，退出后完整落盘。真实缓存的翻译、对唱和 Journey 名称回放通过。重复打包测试在整理阶段向旧输出放入过期资源，再重新打包，确认旧资源被清除；最终 0.7.1 ZIP 内资源集合与当前构建完全相同，CRC、SHA-256 和可执行文件／前端内容检查通过。热替换的普通／debug 测试另覆盖了 DPR 1 与 1.5。

## 范围与保留限制

评分缓存依赖已解析歌词数组不被原地编辑；当前加载、显示及补全路径均通过新数组／新结果更新。以后添加歌词编辑器时必须延续这一约定或显式失效。

未做第三方 vendor 全量审计、所有线上歌词服务的可用性保证、整夜运行或 GPU 利用率／显存分析。线上歌曲身份、音源授权和跨地区别名仍依赖外部数据；不确定的多歌手别名保留人工确认。已有构建包体积提示仍存在；它与本次已复现的排序阻塞不同，不通过隐藏警告或改写构建阈值处理。没有据此宣称项目不存在其他 bug。
